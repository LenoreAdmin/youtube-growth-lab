# V3 – Prediction and Decision Engine

## Architecture and compatibility

V3 retains existing FastAPI, OAuth, Cron, Neon connection and release migration configuration. The sync now calls `prediction_v3.py`; V1 prediction code remains for compatibility and its regression tests. Existing records are retained. No production database has been accessed or changed during local development.

Migration `0004_prediction_audits.py` adds only `prediction_audits`, keyed by existing forecast ID, with a model-run reference, prediction-time metadata, feedback and prioritized hypotheses. No backfill rewrites existing forecasts. Legacy forecasts without provenance audits are excluded from the V3 learner. All existing migrations remain unchanged.

## Forecasts and reproducibility

24h / 168h / 720h forecasts preserve the input feature dictionary, origin/target timestamps and V2 growth regime. Every forecast has a ModelRun, including cold-start baselines. Stored records contain version, library versions, fit time/cutoff, feature names, missing indicators, regime encoding, training IDs, calibration IDs, residuals, baseline scale, evaluation and accepted model parameters. StandardScaler means/scales and Ridge coefficients/intercept permit numerical reproduction; rejected validation candidates are also recorded.

Features: velocity, acceleration, CTR, retention-curve average, watchtime efficiency, watch minutes, subscriber conversion, search/suggested/external traffic shares, age and regime. Missing observations retain explicit flags; zero is not treated as a known missing value. Existing analytics and traffic reports supply features; no additional API scopes or endpoints are introduced.

Learning stages:

- Cold start: observed velocity baseline. No fitted feature weights or invented confidence percentage.
- Adaptive scale: at least 30 non-overlapping verified outcomes from at least five videos.
- Ridge challenger: at least 80 outcomes / ten videos; at least 40 earlier training rows from five videos, at least 20 later validation rows. Validation videos are excluded from candidate training. Accept only if MAE improves at least five percent against the better raw/adaptive baseline. The accepted model is then refitted on available eligible history.
- At most the newest 1,000 candidate rows per horizon are considered. Time-budget checks interrupt training-data inspection safely. For larger catalogues, separate training jobs and precomputed provenance should be considered; this version intentionally makes no infrastructure changes.

## Organic-only learning gate

New forecasts initially describe total counters conditional on organic future growth. The origin counter is NOT claimed to be a verified organic lifetime count. Forecasts with currently known advertising are skipped by the existing sync.

Before any outcome can train or calibrate V3, the system verifies the 32 days before origin through the observed outcome, including Pacific calendar boundary days. This covers input windows and the growth baseline. Traffic-report periods must collectively cover every day, have all matching daily analytics rows, and agree in aggregate view counts. Any overlapping report with ADVERTISING views excludes the sample. Missing, delayed, suppressed, mismatched or incomplete reports remain insufficient. Counter corrections also exclude samples. An earlier eligibility decision is never blindly trusted: source reports are rechecked as of each new forecast cutoff, so later observed paid corrections invalidate subsequent training eligibility.

Classification is based on Google's aggregate traffic reporting; it cannot certify attribution that Google does not expose. Conservative coverage may exclude clean videos, particularly new uploads with fewer than 32 prior days. This is preferable to training an organic model on unknown traffic. Unknown/legacy/paid samples never enter the V3 model. Previously produced predictions remain immutable even if later feedback excludes their observations.

## Confidence and 100k / 1M targets

Explicit statuses include `insufficient_data`, `already_reached_total_counter`, and `empirical_conditional_estimate`. Thresholds refer to reaching the TOTAL counter by the stated horizon under organic future-growth assumptions. They are not a probability of verified organic lifetime views.

Calibration uses saved out-of-sample errors from the same model family, content type and growth regime. Only the latest eligible error per video is used. At least 30 distinct videos, no more than two missing numerical feature groups and a known regime are required. Each target additionally needs at least five supporting observations on either side. Unsupported tails return null probability with `insufficient_data`. Reported probability bands use a Wilson interval; channel-wide temporal dependence and distribution shift remain limitations, so confidence is labelled `empirical_limited`, never a causal certainty.

With Sealandmusic's initial data, prolonged `insufficient_data` is expected. Uncalibrated ranges are explicitly scenarios, not confidence intervals. Outcomes record signed/absolute error, actual observation time, interval hit and provenance status. Future eligible errors change adaptive scaling, validation and calibration.

## Experiment and decision links

Registration freezes IDs of forecasts already available for that video. Memory outcomes and the authenticated memory API expose linked predicted/actual values and errors. Prediction audits also record experiments known at prediction time. Existing success/failure memory remains available; its old potentially unverified aggregate strategy feature is not used to train the V3 organic model.

Recommendations for positioning, audience, musical content/format, title/thumbnail, hook and release sequence are persisted as testable hypotheses. Priority reflects data completeness, current regime, watchtime weaknesses and, when accepted, learned predictive coefficient associations. Association is not causal uplift: the engine does not claim that changing a feature will cause growth. Each recommendation proposes preregistration, one changed dimension and controlled comparisons. It performs no channel actions and does not automatically activate experiments.

The dashboard displays confidence/status, goals, regime, model version and prioritized tests. `GET /api/models/{run_id}` is authenticated and returns reproducibility/evaluation metadata. Run IDs are supplied in forecast audits.
